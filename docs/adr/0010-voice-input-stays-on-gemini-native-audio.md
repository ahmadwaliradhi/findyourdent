# Voice input stays on Gemini native audio; ElevenLabs is ruled out without a test

The product owner asked for ElevenLabs speech-to-text to be evaluated against Gemini native audio for voice complaints (spec 01, H11). We ruled ElevenLabs out on its trade-offs alone, before any comparison. The hackathon requires the Google Cloud stack and scores Google Cloud architectural depth and a "Best use of Google Cloud AI tools" award, which a third-party speech API weakens. Patient voice notes are health-related personal data, and sending them to another processor outside Indonesia would need its own disclosure and lawful basis under UU 27/2022. It would also add a vendor key and cost. And Gemini hears the voice note in the one Guidance call (ADR 0009), so the transcript, the answer and Gemini's own red flags come from a single multimodal step; a separate speech-to-text vendor would put an extra call in front of it. No transcription score would outweigh these, so the evaluation measures Gemini alone: production as it is against production with the dental term list in the stable Guidance instruction (docs/evaluations/voice-input.md). Those results decide whether the term list goes into production; they do not reopen the vendor choice. Revisit only if Gemini native audio is withdrawn or the hackathon's Google Cloud requirement is lifted.
